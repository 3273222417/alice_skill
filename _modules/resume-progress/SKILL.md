---# 项目护航 · 全量进度保存与恢复协议（Resume-Progress / 保驾护航）

本 Skill 专为该长期项目保驾护航：**PUBG(TslGame.exe+BattlEye) 端游外部 ESP / UE4 全局与实体定位**。核心目标：无论上下文被截断、机器重启/蓝屏、对话被清除，用户只要说“**恢复当前进度**”，就能从断点无缝继续，绝不白做。

## 触发词（出现即执行）
- “恢复当前进度”“继续当前进度”“接着上次继续”“护航/保驾护航”“先保存当前进度”
- “上下文断了/截断了/被清除了”“重启/蓝屏/崩溃后继续”“防止白做/别丢进度”

## 固定项目路径
- 工作区根：`C:\Users\Administrator\Documents\游戏歪瓜`（唯一 git 仓库）
- `C:\Users\Administrator\Documents\游戏歪瓜\PROGRESS.md` —— **全量主进度**（append-only，时间戳条目）
- `C:\Users\Administrator\Documents\游戏歪瓜\CONVERSATION_LOG.md` —— **全量对话原文**（用户消息逐字 + Leila 回复要点，append-only）
- 项目内置一份本 Skill 副本：`C:\Users\Administrator\Documents\游戏歪瓜\skills\resume-progress\`（随仓库提交，防全局技能目录丢失）
- 若在其他项目工作：先向上查找含 `PROGRESS.md` 的目录；找不到则取 cwd。

## 每次必做（不等回合结束，实时执行）
1. **收到任何新用户消息**：先把该消息逐字追加到 `CONVERSATION_LOG.md`，再做别的。
2. **每完成一步/一次工具调用/一个决策/一个实验结果**：立即向 `PROGRESS.md` 追加带时间戳完整条目，包含：时间、步骤、输入、关键输出、判定、真实成果（地址/偏移/结构/词典/快照 hash）、产物文件路径、校验/证据、下一步动作。真实成果必须全量写入，不只写摘要。
3. **回合结束前**：把 Leila 回复要点追加进 `CONVERSATION_LOG.md`。
4. **里程碑后**：`git add -A && git commit -m "progress: <本步摘要>"`（在项目根执行）。
5. **新回合/新上下文第一步**：先读 `PROGRESS.md`（大文件先读尾部最新条目，再补读关键段）+ `CONVERSATION_LOG.md` 最近内容，恢复现场再动手。
6. **永不宣称** PROGRESS.md 里没有的进度；不确定写“待验证”，禁止编造。

## 恢复流程（用户说“恢复当前进度”）
1. 读 `PROGRESS.md` 尾部最新全量条目 + `CONVERSATION_LOG.md` 最近内容；必要时读 git log。
2. 从 PROGRESS.md 最后一条“下一步”继续；**不重复已关闭/已失败的路线**；文件中“勿重复验证”的事实直接采信。
3. 若上回合产物未入库：先 `git add -A && git commit` 归档再继续。
4. 恢复后向用户报告：从第几步恢复、当前卡点、下一步动作。

## 项目防事故护栏（重要，防止再次蓝屏/重启/白做）
- 本项目事故史：全盘物理内存扫、GPU-MMIO 区读取曾导致崩溃/蓝屏/重启 → **禁止全盘物理扫、禁止碰 GPU/设备 MMIO**。
- 只做受控窄扫（有边界、命中即停）；读取目标进程只读，非必要不写。
- 变更前先备份原文件/快照；原始与派生产物分开存（如 data_dump/）。
- 目标不稳定时先记录现场（PID、CR3/session 文件、目标 VA、已有词典），保证可复现。
- 一次只改一个变量验证；以真实 runtime 读取为准，不以旧脚本/旧日志推断。
- 读通道依赖现场（Asusgio3/AsIO3 + CR3）时，先探测再开跑；通道失效就停手记录，不硬扫。

## 完成/证据口径
- 报成功 = 结果 + 关键证据 + 可复现步骤 + 产物路径 + 剩余限制，全部同步写入 PROGRESS.md 后才算数。
